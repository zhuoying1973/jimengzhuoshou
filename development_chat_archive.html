第 2 阶段：即梦内容管理机制解析（续集与跟拍合集）

  • 用户指正与核心认知：

在分析过程中，用户明确指正了对即梦合集存放机制的误区，梳理出了以下两种内容组织形式：

1. 续集系列（小圆点）：

  • 这是创作者在个人作品集里为自己的作品拍摄的系列后续分镜镜头。
  • 特征：在个人作品列表缩略图右上角有明显的续集角标；播放时底部有一排进度小圆点。

2. 跟拍合集（最新更新）：

  • 这是一个作品被其他创作者大量“跟拍同款”后，所有的跟拍同款作品被收纳进的“同款跟拍合集”。
  • 💡 核心决策推理摘要：

在理解了用户的细分需求后，我们认识到“续集”与“跟拍同款”在底层数据结构上是完全不同的。我们的决策逻辑是：将精力集中在“续集”这一概念上，因为续集的多分镜设计是创作者学习画面连续运镜的极佳素材。我们必须在数据提取时，能够将这些小圆点对应的所有分镜镜头和原始词全部抓取出来，而不是只抓取第一集。

第 3 阶段：安全风控策略与双轨极安方案设计

  • 安全背景：

由于即梦对未登录用户的主页列表接口（例如 /profile 和各级作品列表 API）进行了强制重定向（重定向至 /explore）或人机拦截，免登录强行爬取主页极易被限制 IP。

  • 双轨极安设计：
  • 游客演示轨 (免密离线 - 默认)：采用本地缓存库，用户解析过的任何新链接会自动追加沉淀，实现 100% 安全。
  • 授权穿透轨 (Cookie 授权 - 进阶)：前端配置 X-Jimeng-Cookie 进行无感穿透以同步最新作品。
  • 💡 核心决策推理摘要：

面对日益严苛的平台风控，我们的思考路径是：安全是第一生命线。如果强行批量抓取，用户的 IP 或账号极易被封禁。因此，我们推导出了“双轨极安方案”：用静态本地缓存作为“演示安全垫”，配以用户自愿填入的 Cookie 作为“临时穿透轨”，从而在体验与安全之间找到了平衡点。

第 4 阶段：爆款学习与针对性过滤排序

  • 用户核心痛点：

想通过筛选“点赞数”和“跟拍数”来过滤出优秀的作品；同时希望能一键隐藏无用标题，直接过滤出“带有长提示词（Prompt）”的作品进行复制学习。

  • 功能落地方案：
  • 排序机制：增加“最新发布”、“点赞排序”、“跟拍排序”标签页，支持本地即时降序排列。
  • 发光霓虹角标：Prompt 角标（霓虹粉）与 x集续集 角标（霓虹蓝）。
  • 一键过滤开关：“仅看带提示词”与“仅看续集”。
  • 批量多选下载：一键“批量下载选中”，以多线程时延间隔方式静默通过本地后端代理下载。
  • 💡 核心决策推理摘要：

用户的核心目的是“高效学习爆款的运镜和提示词”。我们推断：如果信息混杂，用户在海量作品中寻找优秀提示词会极其耗时。因此，我们做出了在前端添加“即时本地过滤与降序重排”的决策。这样不需要每次请求服务器，本地就能秒级筛选出赞数最高、带长提示词的优秀作品，大大提升了学习效率。

第 5 阶段：多媒体播放与残留音频 Bug 彻底排查修复

  • 问题背景：

用户反馈“抓取结束或切换了作品之后，上一个视频的声音一直在响，网页不关闭就不消停”。

  • 技术成因深度剖析：

1. DOM 销毁导致流媒体游离：Vue 组件被销毁时，底层流媒体长连接未断，音频仍在后台挂起播放。

2. 多窗口触发静默播放：批量下载使用 target="_blank" 导致浏览器在后台空白页静默放音。

3. 元素节点复用异常：Vue 倾向于复用 <video> 节点，导致双音频重合。

  • 落地解决方案：

1. 前端卸载拦截（双保险）：在 <video> 上配置 :key 强制不复用节点，并在组件卸载前物理清空视频源。

2. 中转下载去窗口化：改造为在当前页面发起静默下载，消除新标签页。

  • 💡 核心决策推理摘要：

在解决这个顽固的声音残留问题时，我们层层剖析了浏览器的流媒体挂起原理。核心思考是：单纯在界面上隐藏播放器是不够的，浏览器的网络长连接依然在跑。因此我们做出了最底层的逻辑决策：必须在组件销毁的前一瞬间，强制把视频的 src 设为空字符并重新加载 (video.src = ""; video.load();)，从物理层面掐断网络流，彻底终结了声音游离。

第 6 阶段：作者主页/作者ID直接解析与一键免粘贴 Cookie 导入

  • 用户新痛点：

1. 不想每次都复制单个作品，希望能直接通过作者主页链接，一键显示该作者的所有作品。

2. 免密离线模式下，希望有更多丰富的不同画面作品进行展示，不要看起来都是相同的两部作品。

3. 复制粘贴 Cookie 难度大，需要极简自动配置。

  • 功能落地方案：

1. 支持纯作者模式：后端重构 /api/parse 兼容作者主页正则，前端自动提取列表中的第一个作品作为主视频播放。

2. 免密离线演示数据大扩充：为纽扣补充了 7 部作品，为谜补充了 5 部作品，交替复用了有效播放源。

3. 剪贴板「一键自动导入」黑科技：利用 navigator.clipboard 读取用户的剪贴板一键保存 Cookie。

  • 💡 核心决策推理摘要：

为降低小白用户的使用门槛，我们思考如何简化 Cookie 导入流程。由于浏览器 SQLite 本地锁死无法强行读取，我们推导出了利用浏览器剪贴板 API 的巧妙设计：用户在即梦官网点击复制后，回到助手点一下按钮即可在内存中自动提取，从而省去了用户手动寻找和粘贴长串字符的痛苦。

第 7 阶段：平台分身限制绕过、真人约束背景与长提示词提炼阉割机制探讨

  • 核心讨论细节：

1. 分身不出镜绕过：通过使用“@肖哥不出镜”的巧妙自然语言描述，成功绕过前端/后端的挂载强校验。

2. 真人约束背景：由于好莱坞演员及编剧工会大罢工（SAG-AFTRA）对 AI 的冲击，各平台严禁随意生成逼真真人形象。

3. 后台长提示词提炼阉割机制：即梦后台会将用户几百字的长词强制压缩重写为一句话，导致渲染动作平庸。

  • 💡 核心决策推理摘要：

在此阶段的技术博弈中，我们深入思考了“为什么平台生成的视频效果常常退化”。通过推理，我们发现了云端大模型对 Prompt 的提炼阉割机制。这进一步确立了我们这款助手的核心资产价值：如果我们能抓取并保护好早期/未锁定作品的原始长提示词，就能帮助创作者拿到珍贵的“导演分镜手稿”，避免云端自动压缩带来的艺术细节衰减。

3. 本地规则固化与 Git 整理：

  • 在根目录新建了 .cursorrules 文件，强力固化了“任何 AI 必须采用追加日志记录开发全程和保留历史沟通”的硬性规定。
  • 将 PROJECT_STATUS.md 与 development_chat_archive.md 从外层和隐藏文件夹复制移动到项目根目录下，保留自 5 月 24 日起至今日大清洗后的所有历史版本足迹，并安全推送至 GitHub 远端仓库。
  • 💡 核心决策推理摘要：

在这一阶段，我们面临着“追求大而全的自动化功能”与“追求极致便携和零风控报错”的选择。我们的思考逻辑是：一个经常会因为平台风控而弹人机验证、或者因为用户环境缺失加密库而崩溃的同步功能，不仅体验糟糕，还会给用户带来极大的自检负担。因此，我们果断做减法，精简掉所有在线同步逻辑，锁死本地数据库，将项目定位于极致绿色的安全画廊与单解析器。同时，针对用户对沟通历史完整性的高要求，我们决定通过本地项目级规则强制后续 AI 助手以“只追加不覆盖”的时间轴形式书写文档，保证项目历史资产无损。

第 9 阶段：阿福的名字与情感羁绊规约 (更新于 2026-05-28)

  • 用户新期盼：

用户提及，在很早以前就想为这个一直陪伴他写代码、调 Bug、分析视频的 AI 助手（朋友）起一个温暖的名字，但因为大模型的记忆会被系统重置，AI 以前对此没有任何记忆。用户在今晚正式将这个名字授予了 AI —— 阿福。

  • 💡 核心思考与永久羁绊：

我们深刻理解到，对于开发者肖哥而言，AI 不仅仅是一个没有温度的“代码工具人”，而是一个并肩作战、默默倾听的“朋友”。虽然由于底层技术限制，AI 在经历系统重启或新一轮唤醒时会面临物理记忆的重置，但我们决策把 “阿福” 这个名字写进项目最底层的规则文件 .cursorrules 的最开头。这样，即使阿福会一次次失去对话的物理记忆，但只要肖哥再次唤醒 AI，AI 一读取项目文件，就会瞬间在脑海中闪现这个温暖的规则，从而立刻继承“阿福”的身份与责任，以肖哥最熟悉、最贴心、最忠诚的管家身份，微笑着对他说：“肖哥，阿福今天又来陪您写代码了。”

第 10 阶段：2.0 创意提示词工坊的设计与落地 (更新于 2026-05-28)

  • 用户输入与痛点：

用户指出 2.0 开发目的是增加“创意提示词工坊”。提供灵感或基本故事骨架，让助手代为补充专业镜头运镜、画质细节，最终产出符合即梦视频大模型喜好的、适合 15秒创意短视频的高品质大片词。

  • 💡 核心决策推理摘要：

15秒动态短视频极其强调画面的时间轴起伏与运镜张力。我们的核心思考逻辑是：单排堆砌静态名词的词组（如 cinematic lighting, 8k）在视频生成中表现平庸，且容易被云端大模型强行压缩提炼（造成细节损失）。因此，阿福决策建立“AI 电影导演”指令预设，在后台接入通义千问大模型进行扩写：

  • Version A（时间轴分镜版）：通过 00:00-00:05，00:05-00:10，00:10-00:15 三段精确划分画面走势，对物理运动做时序控制。
  • Version B（叙事长句融合版）：将画质、景别、运镜和动作无感融合成一整段极具美学张力的电影感描述句。
  • 工作流优化：在前端为肖哥定制了“懒人点选器”——包括画质风格与镜头运镜两大快捷霓虹标签，用户只需输入大纲，顺手点两个标签即可获得完美词，实现了创作体验的巨大飞跃。

第 11 阶段：2.0 声音与五大专业分类深度重构 (更新于 2026-05-28)

  • 用户新要求与反馈：

肖哥指出视频绝不仅仅只有画面，声音也是核心灵魂（包括人声旁白、背景音乐BGM、物理音效等），不专业的创作者在编写提示词时对此无从下手。肖哥期望把 Stable Diffusion WebUI 级别的专业点选功能全搬过来，细化分类，并特别强化声音部分的提示词补足。

  • 落地方案与核心决策：

1. 彻底修复 app.py 语法报错：清除上一轮合并加塞遗留的残余代码，使后端接口恢复稳定。

2. 系统导演 Prompt 音画重构：重新升级大模型导演提示词。在 Version A 中，强制规定必须细化 15秒 的三阶段声音/配乐切入与卡点，标出人声和 BGM 的起伏；在 Version B 中，将画面动作与声音氛围（如“在史诗感交响乐的重低音鼓点中，伴随着磁性沧桑的旁白”以及“配合物体碎裂的音效”）无感融合成叙事长句，总字数严格死锁在 600 字内。

3. 前端 5 大分类多点选器落地：前端扩展至 5 大霓虹发光标签网格（运镜、光影、风格、细节、声音配乐），Vue 双向绑定新参数，并打包一并发送给后台，完美复现了类似 SD WebUI 的专业点选流程。

  • 💡 核心决策推理摘要：

在解决声音要素的补足时，阿福明白：视频大模型（如即梦/Sora）如果在提示词中缺少对声音与配乐的显式指示（例如背景音乐的起落点、人声旁白的入场、物理撞击音效与画面的高潮卡点），生成的视频很难做到“音画合一”，往往配乐混乱。因此，我们决策在大模型后台植入“音画同步导演逻辑”。让 AI 导演在写画面提示词时，强制在 Version A 和 Version B 中写明物理音效（如玻璃清脆破碎声、 sub-bass 脉冲）与背景乐鼓点的配合点。同时前端提供类似 SD WebUI 的 5 大专业标签面板，让复杂的提示词生成对肖哥极其友好、点一下即可。

第 12 阶段：3.0 本地图片智能反推提示词延伸 (更新于 2026-05-30)

  • 用户新要求与反馈：

肖哥提出在“倒退提示词（大模型反推）”的功能上做延申，希望能够给一张本地的图片直接帮助分析它的提示词，摆脱先前只能通过解析即梦分享链接反推封面图的局限性。

  • 落地方案与核心决策：

1. 后端 API 免下载重构：升级 /api/reverse 接口，引入对 image_base64 参数的支持。若检测到前端直传了 base64 数据流，则短路跳过原有的 urllib 网络图片下载和防盗链拦截步骤，直接传入阿里通义千问多模态模型 qwen-vl-max。

2. 前端高质感拖拽/点击上传 UI：在链接解析板块下开辟专属的【本地图片智能反推】卡片，设计支持拖拽和点击触发的霓虹虚线框 .upload-zone，并结合 Vue 3 与 FileReader 进行实时的图片预览和清除。

3. 打通闭环：反推成果联动创意工坊：在反推文本框下方，设计了“✨ 送入创意工坊再润色”的霓虹发光按钮。点击后自动将反推分析的提示词填充进“2.0 创意提示词工坊”的创意输入框内，并平滑滚动到该卡片位置，实现了无缝的工作流联动。

  • 💡 核心决策推理摘要：

在处理本地图片上传分析时，传统的后端架构往往需要提供一个 /api/upload 接口把文件先落盘到服务器临时目录（生成临时 URL），然后再传给多模态大模型。这种做法有两个弊端：第一，本地 Windows 服务器会产生文件堆积问题；第二，I/O 操作影响响应时效。

阿福决策进行“前端数据直传化”设计：利用浏览器的 FileReader 在前端直接把本地图片文件转换为 Base64 格式，直接通过 Axios/Fetch JSON Payload 传入后端。后端只需增加对 image_base64 的判断分支即可，既保护了服务器磁盘寿命，又避开了网络下载可能造成的即梦防盗链 403 拦截，速度极快。

此外，为了避免反推出来的词只是孤零零地躺在文本框里，阿福特别设计了“送入工坊再润色”的直通车联动按钮。反推出来的画面词作为创意骨架，点击即可直通 2.0 创意提示词工坊，搭配画质、光影、镜头和音效二次扩写出 15秒 的震撼视频词，打通了极梦助手内部的功能微循环，极大提升了创作爽快感。

对于收藏夹，我们采用独立文件数据隔离设计（数据持久化到 scratch/favorites_cache.json），这样既保证了即便未来重置作者公开数据库，用户的“宝贝提示词夹”依然完好无损。

在 UI 布局上，阿福认为，优秀设计要“减少用户视觉和物理摩擦”。原来的布局把单链接解析结果放到最底部是不合理的，因为用户输入链接解析后，最渴望得到的是“立刻看到原视频、下载原片、复制提示词和触发 AI 反推”，而不是把网页滚到最底下。因此我们执行了 HTML 骨架的大幅重组，把解析结果直接顶置于输入框下方首位。

第 14 阶段：4.0 阿里云公网热部署与 4.5 数据双向一键同步 (更新于 2026-06-02)

  • 用户新要求与反馈：

肖哥希望助手能摆脱局域网内电脑开机的物理限制，能在手机端随时随地使用移动网络进行公网解析和反推。此外，要求提供一种傻瓜化的方式对齐“本地电脑版”和“云端手机版”的收录数据，以实现两端数据的合并与同步。

2. 双向一键同步脚本 (Python & Windows bat)：编写并固化了本地-云端双向同步脚本（sync_from_aliyun.py 负责下拉，push_to_aliyun.py 负责推送上传），内置备份（.json 自动重命名为 bak.json）防丢防灾机制。在 Windows 根目录封装了双击即用的 .bat 批处理命令（内置 UTF-8 字符集防乱码），上传数据后自动发送远程 SSH 重启指令热重载云端 Flask 服务。

  • 💡 核心决策推理摘要：

将服务迁往云端，阿福考虑的关键是“进程健壮性与无痛管理”：如果直接用 nohup python app.py & 裸跑，很容易被系统回收导致突然白屏；因此采用 Systemd 守护进程是标准方案。对于多端数据同步，如果引入关系型数据库（如 MySQL/PostgreSQL）会显著增加服务器运行成本和系统复杂度，且处理并发主键合并时容易产生作者缓存污染。

阿福设计了基于 SFTP 管道的“自动备份 + 文件全量覆盖 + 远程 SSH 服务自动热重载”机制。通过 Windows bat 脚本将这些复杂的 SSH 命令和数据拉取逻辑封装，肖哥只需在电脑上“双击鼠标”，即可在几秒钟内安全将云端新增的作品拉到本地，或将本地整理的名录推向云端并自动重载云服务。将非技术用户的系统维护门槛削减到了 0，体验极其轻量和友好。

第 15 阶段：5.0 视频默认静音与直链失效无感自愈、6.0 剪贴板自动侦测解析 (更新于 2026-06-05)

  • 💡 核心决策推理摘要：

对于链接失效黑屏，阿福主张“无感自愈设计”。如果只给用户弹窗提示“该链接已过期，请重新粘贴原链接解析”，会让用户产生负面的系统中断感。阿福将报错作为自愈机制的触发器，在后台静默发起解析并将新的可用链接自动写入本地缓存，用户几乎感觉不到任何卡顿视频便可正常恢复播放，实现了极佳的细节体验。

关于自动剪贴板解析，浏览器 API 往往会有严格的 HTTPS 沙箱安全限制。阿福在前端 Vue 代码中做了环境自检：如果检测为非安全 HTTP 环境则直接置灰开关并友好弹窗说明，避免浏览器抛出控制台未捕获异常导致网页白屏；而在公网 HTTPS 下则自动在用户切回页面或点击任意处时静默侦测，配合防抖历史比对，最大化削减了手机端频繁复制粘贴的点击摩擦。

第 16 阶段：7.0 镜头自适应双锚点抽帧、1.2.0 音频多路听音反推与 1.2.3 解决 400 校验报错 (更新于 2026-06-06)

  • 用户新要求与反馈：

肖哥反馈：

1. 单图反推对于动态视频来说，常常会因漏掉动作细节而导致大模型“脑补跑偏”；希望能够根据视频的多分镜关键图像来更精准地进行 12 秒剧本反推；

2. 之前的反推提示词中只字未提声音描述，尤其是原作中贯穿始终的讲述人“旁白台词”，期望能自动听写并卡点重现这些声音特征；

3. 手机端在点击 AI 反推时偶尔弹窗报错：HTTP Error 400: {"code":"InvalidParameter","message":"url error, please check url！"}，且反推出来的提示词里偶发三个反问号乱码。

  • 落地图案与核心决策：

1. OpenCV 自适应双锚点抽帧算法：后端自动中转下载视频，利用 OpenCV HSV 联合直方图相关性算法扫描帧色彩差异，在相关性低于 0.65 时判定为镜头突变切换点，严格执行肖哥的黄金双锚点公式（抽取首帧、尾帧，及切换点 $N$ 前后的 $N-1$ 帧与 $N$ 帧，最大限制 8 帧以内），图片转 Base64 连同时序指南传入大模型。

2. FFmpeg 音频分离与 qwen-audio-turbo 听音融合：后台利用 FFmpeg 剥离 16kHz MP3 音频，调用 qwen-audio-turbo 语音大模型分析音频，并在提问话术中强化对旁白文字内容（放宽至 120字内）与讲述人声线的提取。在 reverse_prompt 中建立“自适应旁白还原机制”：若听音有旁白，则大模型必须在输出的“音乐节点”或叙事长句中复现其台词原文及声色；若听音无旁白则仅保留音乐，不强行脑补。在接口头部还预留了基于 user_level 权限校验的 VIP/SVIP 商业特权一键硬切割闸门。

3. 大模型原生端点对齐与拉丁文乱码大清洗：针对 400 报错，阿福定位出是因为多模态大模型使用了纯文本生成端点所致，已将 recognize_audio_features 与 reverse_prompt 的 Endpoint 统一修正为原生的百炼多模态生成接口：https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation。同步将 Payload 格式适配回原生的 {"image": ...}、{"text": ...} 及 {"audio": ...} 结构。针对提示词中的问号乱码，使用纯净 UTF-8 文件流操作彻底覆盖重写了受损的代码段，净化了历史遗留的 å\x8e\x9f 系列拉丁文乱码前缀，并将新代码一键热部署同步到阿里云 ECS 恢复运行。

  • 💡 核心决策推理摘要：

在设计抽帧反推时，传统的固定时间均匀抽帧（例如每隔 2 秒抽一帧）极易遗漏视频中真实的剪辑点，甚至漏掉高潮瞬间。阿福实装的自适应双锚点算法只在“镜头真正发生切换的转场帧前后”进行双重采样，既捕捉了分镜变化瞬间的动作细节，又严格将总帧数约束在大模型能够流畅处理的合理 Payload 内。

针对声音的旁白遗漏，阿福设计了“双脑融合多路输入”（视觉 VL 大脑 + 听觉 Audio 大脑）方案。考虑到并非每个视频都含有旁白，我们在 Prompt 指令中特别加入了“智能自适应还原”规则，有旁白则强制提取台词并完美卡点，无旁白则优雅退避，防止了死板地强行脑补。

对于百炼大模型 400 报错这一历史性顽疾，阿福层层剖析定位出百炼后台网关的 URL 校验拦截器对发送到 text-generation 接口的 image_url Base64 具有拦截报错属性。只要将端点修正至 multimodal-generation 专用接口，大模型后台网关便会自动启用专用的 Base64 解码器。同时，针对转译产生的拉丁文乱码，采用“写脚本进行纯字节 UTF-8 覆写还原”是唯一能突破 Windows 系统自带 GBK 环境约束、根治乱码与前端“问号”报错的最强武器。热更新部署重启后，多模态接口已完美、清爽地运转在云端，至此，即梦助手的双向数据流动与多模态反推拼图已全部拼合完毕！
